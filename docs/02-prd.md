# 02 PRD：產品需求

版本：0.1（2026-11-08）｜狀態：草稿｜未確認事項標「待確認」

## 1. 使用者與情境

- **使用者**：中小型零售店的庫存/採購人員。
- **情境**：每週要決定上百個品項各補多少貨。現況靠經驗或 Excel 移動平均，旺季缺貨、淡季積壓。

## 2. 問題與目標

| 編號 | 目標 | 使用者價值 |
|---|---|---|
| G1 | 預測每個品項未來 28 天銷量 | 知道接下來會賣多少 |
| G2 | 把預測轉成「補貨點與補貨量」建議 | 不必自己換算 |
| G3 | 用「持有成本＋缺貨成本」比較策略 | 看得到省多少錢，而不只是預測誤差 |
| G4（加分） | 自然語言查詢與情境模擬 | 問「交期延長 3 天會怎樣」 |

## 3. 主流程

1. 使用者開啟網頁，選擇門市與品項。
2. 系統顯示歷史銷量與未來 28 天預測。
3. 使用者輸入現有庫存、交期、服務水準（可選 MOQ）。
4. 系統顯示補貨點、建議補貨量與基準策略的成本比較。

## 4. 使用者故事與驗收條件

**US-1 查看預測**：身為採購人員，我想選品項看未來 28 天預測，以便安排補貨。
- AC-1.1 選擇有效品項與門市後，頁面顯示 28 個日期的預測值。
- AC-1.2 品項不存在時，顯示明確錯誤訊息，不顯示空白圖。

**US-2 取得補貨建議**：身為採購人員，我想輸入庫存與交期後得到建議補貨量。
- AC-2.1 輸入庫存、交期、服務水準後，顯示補貨點與建議補貨量（整數，≥ 0）。
- AC-2.2 設定 MOQ 時，若建議補貨量大於 0，則補貨量不小於 MOQ。
- AC-2.3 輸入不合理（負庫存、服務水準不在 0.5–0.999）時被拒絕並說明原因。

**US-3 比較策略成本**：身為採購人員，我想知道新策略比原本做法省多少。
- AC-3.1 顯示在保留期（28 天）內，本模型與基準策略的總成本與缺貨量。
- AC-3.2 明確標示資料來源（合成資料或真實 M5）。

## 5. 成功指標（目標值，待實測）

| 編號 | 指標 | 目標 |
|---|---|---|
| M-1 | 28 天保留期 RMSSE | 優於 seasonal naive 與 28 天移動平均 |
| M-2 | 模擬總成本（所有策略共用相同服務水準與成本，只換預測） | 低於 28 天移動平均預測的策略 |
| M-3 | 單品項預測 API p95 | < 1 秒（待確認測量方式） |
| M-4 | （加分）LLM 測試集 | 30 題，工具呼叫正確率 ≥ 80% |

## 6. 範圍外

訂單與付款、ERP 串接、使用者登入與權限、多幣別、即時庫存同步。

## 7. 待確認

- 真實 M5 資料的子集範圍（州、品項數）。
- 成本參數（持有成本、缺貨成本）預設值與來源。
- 是否做 LLM 助理（取決於時程）。
