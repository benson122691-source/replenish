# 04 SAD：系統架構

版本：0.1（2026-11-08）

## 1. 架構

```
 data/raw (M5 或合成 CSV)
        │  FR-1
        ▼
 [data.py 載入] → [features.py 特徵] → [baselines.py 基準]
                          │                    │
                          ▼                    │
                  [models.py LightGBM] ◄───────┘ 評估比較
                          │ FR-4
                          ▼
                  [policy.py 補貨策略] → [simulate.py 成本模擬]   FR-5、FR-6
                          │
                          ▼
                  [api.py FastAPI]  /forecast  /replenish  /compare   FR-7~9
                          │
                          ▼
                  [static/index.html 儀表板]    FR-10
```

## 2. 資料流

1. 載入 M5 格式檔 → 長表（一列＝一序列一天）。
2. 以 origin（最後一天減 28 天）切分訓練與保留期。
3. 訓練模型，預測保留期 28 天；與基準比較誤差。
4. 預測值＋交期＋服務水準 → 補貨點與補貨量；在保留期模擬庫存得成本。
5. 預測、模型指標、成本比較寫入檔案（預設）；API 啟動時載入，不在請求時重訓。

## 3. 選型理由

| 項目 | 選擇 | 理由 |
|---|---|---|
| 語言 | Python | 資料與 ML 生態；職缺高頻 |
| 主要模型 | LightGBM | 表格型時間序列表現穩定、訓練快 |
| 對照模型 | PyTorch 簡單網路（加分，待確認） | 驗證「是否需要更複雜模型」 |
| API | FastAPI | 自動文件、型別驗證 |
| 前端 | 單頁 HTML＋JS 圖表 | 範圍小，不需前端框架 |
| 儲存 | 檔案（MVP）；MySQL（待確認，視時程） | 先求可用，再升級 |
| 部署 | Docker；雲端平台待確認 | 一鍵啟動，可降級為操作影片 |

## 4. 失敗處理

| 情境 | 處理 |
|---|---|
| 找不到 M5 檔案 | 腳本改用合成資料並印出警告；結果標示「合成」 |
| 模型檔不存在 | API 啟動失敗並說明需先執行訓練腳本 |
| 輸入無效 | 400/404/422，回傳欄位與原因 |
| 序列資料過短 | 該序列跳過並記錄 |
| 雲端部署失敗 | 提交操作影片與測試紀錄，如實標註 |
